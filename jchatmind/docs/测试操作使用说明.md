# JChatMind 测试操作使用说明

## 1. 环境准备

### 1.1 JDK 版本要求

- **JDK 17** 或更高版本（推荐 JDK 21）
- 验证命令：
  ```bash
  java -version
  ```

### 1.2 Maven 配置

项目自带 Maven Wrapper（`mvnw` / `mvnw.cmd`），**无需单独安装 Maven**。

如需使用系统 Maven：
- Maven 3.8+
- 验证命令：`mvn -version`

### 1.3 IDE 配置（IntelliJ IDEA）

1. 打开项目：`File → Open → 选择 jchatmind 目录`
2. 确认 SDK 设置：`File → Project Structure → SDK → JDK 17+`
3. 启用注解处理器（Lombok）：`Settings → Build → Compiler → Annotation Processors → Enable`
4. 确保 Maven 自动导入：`Settings → Build → Build Tools → Maven → Auto-import`

### 1.4 数据库要求

> **测试使用 H2 内存数据库，无需安装任何外部数据库。**

H2 在 `pom.xml` 中以 `test` scope 引入，测试运行时自动创建和销毁。

## 2. 快速开始

### 2.1 运行全部测试

#### 命令行方式

```bash
# Windows
cd jchatmind
mvnw.cmd test

# Linux / Mac
cd jchatmind
./mvnw test
```

#### IDE 方式（IntelliJ IDEA）

1. 在 `src/test/java` 目录右键
2. 选择 `Run 'All Tests'`
3. 或使用快捷键 `Ctrl+Shift+F10`

#### 脚本方式

```bash
# Windows
scripts\run-tests.cmd

# Linux / Mac
chmod +x scripts/run-tests.sh
scripts/run-tests.sh
```

### 2.2 运行指定测试

#### 运行单个测试类

```bash
# 运行 Agent 核心测试
mvnw.cmd test -Dtest=JChatMindTest

# 运行工厂测试
mvnw.cmd test -Dtest=JChatMindFactoryTest
```

#### 运行单个测试方法

```bash
# 运行指定方法
mvnw.cmd test -Dtest=JChatMindTest#testRunBasicChat_NoToolCalls
```

#### 按包运行测试

```bash
# 运行所有 Service 层测试
mvnw.cmd test -Dtest="com.kama.jchatmind.service.*"

# 运行所有 Controller 层测试
mvnw.cmd test -Dtest="com.kama.jchatmind.controller.*"

# 运行评估框架测试
mvnw.cmd test -Dtest="com.kama.jchatmind.evaluation.*"
```

#### Maven 命令速查表

| 命令 | 说明 |
|------|------|
| `mvnw test` | 运行全部测试 |
| `mvnw test -Dtest=类名` | 运行指定类 |
| `mvnw test -Dtest=类名#方法名` | 运行指定方法 |
| `mvnw test -Dtest="包名.*"` | 按包运行 |
| `mvnw test -pl jchatmind` | 指定模块运行 |
| `mvnw test -Dmaven.test.failure.ignore=true` | 忽略失败继续 |
| `mvnw -Dtest=类名 -DfailIfNoTests=false test` | 防止无匹配时报错 |

## 4. Postman 接口测试操作

### 4.1 导入 Collection

1. 打开 Postman，点击左上角 **Import** 按钮
2. 选择 **File** 选项卡
3. 浏览到 `jchatmind/postman/JChatMind_API.postman_collection.json`
4. 点击 **Import** 完成导入
5. 左侧面板出现 **JChatMind API** Collection

### 4.2 配置环境变量

Collection 自带变量定义，默认配置：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `baseUrl` | `http://localhost:8080` | 后端服务地址 |
| `agentId` | (空) | 自动从创建响应中提取 |
| `chatSessionId` | (空) | 自动从创建响应中提取 |
| `chatMessageId` | (空) | 自动从创建响应中提取 |
| `knowledgeBaseId` | (空) | 自动从创建响应中提取 |
| `documentId` | (空) | 自动从创建响应中提取 |

如需修改 `baseUrl`：点击 Collection → Variables 选项卡 → 修改值。

### 4.3 运行测试

**前提**：先启动后端服务 `mvnw spring-boot:run`

#### 运行单个请求

1. 展开 Collection 中的 Folder（如 Agent Management）
2. 选择请求（如 POST /api/agents - Create Agent）
3. 点击 **Send** 按钮
4. 查看下方 **Test Results** 选项卡

#### 运行整个 Folder

1. 右键点击 Folder 名称
2. 选择 **Run folder**
3. 查看运行结果

#### 运行 Collection Runner

1. 点击 Collection 右侧 **▶ Run** 按钮
2. 勾选要运行的请求
3. 设置迭代次数（默认 1）
4. 点击 **Run JChatMind API**
5. 查看运行结果摘要

#### 查看测试结果

每个请求的 Tests 脚本会自动验证：
- 状态码（200/201）
- 响应体结构（code, data 字段）
- 业务字段存在性
- 响应时间（< 2000ms）

### 4.4 SSE 流式响应测试

#### 使用 Postman 测试 SSE

1. 选择 SSE Streaming Folder 中的 `GET /sse/connect/{chatSessionId}`
2. 替换 `{chatSessionId}` 为有效的会话 ID
3. 点击 Send
4. Postman 会显示 SSE 事件流

#### 断点续传测试步骤

1. **建立连接**：`GET /sse/connect/{chatSessionId}`
2. **发送消息**：`POST /api/chat-messages`，触发 AI 回复
3. **中断连接**：手动取消请求
4. **重新连接**：再次 `GET /sse/connect/{chatSessionId}`
5. **验证**：检查是否收到未读消息

## 5. Git Pre-commit Hook 使用

### 5.1 首次配置

在项目根目录执行：

```bash
git config core.hooksPath jchatmind/.githooks
```

验证配置：

```bash
git config core.hooksPath
# 输出: jchatmind/.githooks
```

Linux/Mac 需要添加执行权限：

```bash
chmod +x jchatmind/.githooks/pre-commit
```

### 5.2 工作流程

```
git commit → pre-commit hook 触发
  ├── [1/2] 运行单元测试 (mvnw test)
  │   ├── 通过 → 继续
  │   └── 失败 → COMMIT REJECTED，退出码 1
  └── [2/2] 编译检查 (mvnw compile)
      ├── 通过 → All checks passed，允许提交
      └── 失败 → COMMIT REJECTED，退出码 1
```

**示例输出（成功）：**
```
==========================================
 Running pre-commit quality checks...
==========================================

[1/2] Running unit tests...
 Unit tests passed.

[2/2] Checking compilation...
 Compilation check passed.

==========================================
 All pre-commit checks passed!
==========================================
```

**示例输出（失败）：**
```
[1/2] Running unit tests...

============================================
 COMMIT REJECTED: Unit tests failed!
 Please fix failing tests before committing.
============================================
```

### 5.3 临时跳过（不推荐）

```bash
git commit --no-verify -m "紧急修复"
```

> ⚠️ **不推荐**：跳过 hook 可能导致有问题的代码被提交。

## 6. 评估报告解读

### 6.1 评估指标说明

| 指标 | 说明 | 计算方式 |
|------|------|---------|
| 准确率 (Accuracy Rate) | 通过的测试用例占比 | 通过数 / 总数 |
| 幻觉率 (Hallucination Rate) | 检测到幻觉的用例占比 | 幻觉数 / 总数 |
| 工具调用成功率 | 正确调用工具的用例占比 | 工具调用正确数 / 工具调用总数 |
| 平均响应时间 | 所有用例的平均响应耗时 | 总耗时 / 总数 |
| 相关性得分 | 回复与预期的匹配程度 | 基于关键词匹配 + 内容规则的加权得分 |

### 6.2 基线标准

| 类别 | 指标 | 基线阈值 |
|------|------|---------|
| 单轮对话 | 准确率 | ≥ 90% |
| 多轮对话 | 准确率 | ≥ 85% |
| RAG 问答 | 准确率 | ≥ 80% |
| 工具调用 | 成功率 | ≥ 95% |
| 无知识库场景 | 幻觉率 | < 15% |
| 有知识库场景 | 幻觉率 | < 5% |

### 6.4 如何添加新的测试用例

#### JSON 文件格式

```json
{
  "id": "TC-ST-021",
  "name": "新测试用例名称",
  "description": "用例描述",
  "input": {
    "userMessage": "用户输入内容",
    "conversationHistory": [],
    "availableTools": [],
    "knowledgeBase": null
  },
  "expected": {
    "shouldCallTool": false,
    "expectedToolName": null,
    "expectedKeywords": ["关键词1", "关键词2"],
    "shouldContain": ["必须包含的内容"],
    "shouldNotContain": ["不应包含的内容"],
    "expectedBehavior": "期望行为描述"
  },
  "evaluationCriteria": {
    "accuracyWeight": 1.0,
    "hallucinationCheck": false,
    "relevanceCheck": true
  }
}
```

#### 添加步骤

1. 选择对应的 JSON 文件（如 `single_turn_cases.json`）
2. 在 `testCases` 数组中添加新用例
3. 在 `AgentEvaluationTest.java` 的 `initMockResponses()` 中添加对应 mock 响应
4. 运行测试验证：`mvnw test -Dtest=AgentEvaluationTest`

## 7. 常见问题与排错

### 测试编译失败怎么办

```bash
# 清理并重新编译
mvnw clean compile

# 如果 Lombok 报错，确认 IDE 安装了 Lombok 插件并启用注解处理器
```

### 测试运行超时

- Controller 测试需要启动 Spring 上下文，首次运行较慢（10-30 秒属正常）
- 如果持续超时，检查是否有端口占用或依赖下载问题：
  ```bash
  mvnw test -X  # 开启 debug 输出
  ```

### Mock 注入失败

- 检查 `@ExtendWith(MockitoExtension.class)` 是否存在
- 检查 `@Mock` 和 `@InjectMocks` 注解是否正确
- Controller 测试使用 `@MockitoBean` 而非 `@Mock`

### Postman 连接失败

1. 确认后端服务已启动：`mvnw spring-boot:run`
2. 检查端口是否正确（默认 8080）
3. 检查 `baseUrl` 变量是否正确
4. 检查防火墙/代理设置

### Pre-commit Hook 不生效

```bash
# 1. 确认 hook 路径配置正确
git config core.hooksPath

# 2. 确认文件有执行权限（Linux/Mac）
chmod +x jchatmind/.githooks/pre-commit

# 3. 手动测试 hook
sh jchatmind/.githooks/pre-commit
```

### H2 数据库相关错误

- H2 仅在 test scope 使用，正常测试不需要任何数据库配置
- 如果出现 H2 相关错误，检查 `src/test/resources/application.yaml` 是否存在 H2 配置
